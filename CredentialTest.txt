========================================
MIGRACIÓN A PHP
========================================

Todas las páginas .html pasaron a .php. Ver README.md para la guía
completa de instalación en XAMPP.

Cambios principales:

1. HEADER Y FOOTER
   - Antes: los inyectaba components.js con innerHTML.
   - Ahora: partials/header.php y partials/footer.php, incluidos con PHP.
   - Ventaja: se ven aunque el JavaScript esté deshabilitado y el enlace
     activo del menú se marca en el servidor.

2. CONFIGURACIÓN EN .env
   - .env        → variables globales del proyecto.
   - .env.local  → variables locales de cada computadora (pisa al .env).
   - Se leen con env('CLAVE') desde cualquier página.

3. SESIONES REALES
   - Antes: el login validaba en JavaScript y guardaba en localStorage.
   - Ahora: index.php valida en el servidor y usa $_SESSION.
   - Las páginas internas llaman a require_login().
   - logout.php cierra la sesión y regenera el identificador.

4. DATOS EN data/
   - credentials.json, students.json, institution.json se movieron a data/
     y quedaron bloqueados por .htaccess (ya no se pueden abrir por URL).
   - attendance.json y comments.json se crean solos al usar el sistema.

5. FORMULARIOS QUE GUARDAN DE VERDAD
   - Asistencia      -> data/attendance.json
   - Alta de alumnos -> data/students.json
   - Configuración   -> data/institution.json
   - Comentarios     -> data/comments.json
   - Usuarios nuevos -> data/credentials.json (con password_hash)
   - Todos con token CSRF.

6. ESTADÍSTICAS CALCULADAS
   - El dashboard, los reportes y las notificaciones ya no tienen números
     fijos: se calculan en PHP a partir de data/students.json.

7. BASE DE DATOS OPCIONAL
   - sql/sigah.sql crea el esquema en MariaDB.
   - Se activa con DB_ENABLED=true en el .env.
   - Mientras esté en false, el sistema usa los JSON.

========================================
FLUJO DE AUTENTICACIÓN
========================================

1. El usuario abre http://localhost/sigah/
2. Ingresa email/usuario y contraseña (formulario POST).
3. index.php busca el usuario en data/credentials.json.
4. Verifica la contraseña: password_verify() si es un hash,
   comparación directa si es de los usuarios de ejemplo.
5. Si coincide, guarda los datos en $_SESSION y redirige a home.php.
6. Cada página protegida llama a require_login().
